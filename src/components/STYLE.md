# 公共出图样式：BanG Dream! GUIDE

参考：[官方攻略指南](https://bang-dream.bushimo.jp/guide/)及其 [CSS](https://bang-dream.bushimo.jp/wordpress/wp-content/themes/bang-dream_gbp_v2/assets/css/guide/style.css)。本次调整仅涉及 `src/components` 和 `src/image` 公共绘制层，业务视图、接口、数据模型和游戏素材不变。

## 样式分析与映射

官网的主要特征是粉色信息层级、半透明白色内容区、粉青柔光背景和少量星形装饰。对应关系如下：

| 官网元素 | 原项目表现 | 公共层实现 |
| --- | --- | --- |
| 主色 `#ff3b72 → #ff79a9` | 标题底图、灰色标签和零散硬编码颜色 | `image/theme.ts` 统一颜色与渐变 |
| 整页大标题 | 固定 `title.png` 位图 | 按用户反馈恢复原粉白胶囊位图，保留真实尺寸和 110px 逻辑高度 |
| `.sub-Section` 20px 圆角白卡片 | 35px 圆角及独立标题页签 | 连成一体的白色卡片和整宽渐变标题带 |
| 标题右下点阵 | 无统一装饰 | 直接使用官网 `bg_dot_right-end.png`，右下对齐、125px 宽、保留素材透明度 |
| `.sub-Nav` 胶囊外形 | 深灰实心标签 | 按用户反馈保留实心胶囊，恢复原 `#5b5b5b` 灰底白字 |
| 正文 `#282828` / 次文 `#716868` | 多种中灰色 | 正文、提示、图表刻度统一主题颜色 |
| 柔和粉色投影 | 小范围灰粉色投影 | 缓存九宫格粉色阴影，适配长列表 |
| 粉青底、白色图标及描边文字 | 暖色随机纹理 | 本地打包官网原图，按原 CSS 分三层平铺；保留原背景模式 |

官网使用 Noto Sans JP、M PLUS Rounded 1c 等日文字体。这里保留项目自带的 `old` / 方正黑体：中文覆盖、测量结果和离线部署更加稳定。背景图案改为直接使用官网原素材，来源与尺寸记录在 `assets/BG/guide/README.md`，运行时无需访问官网。

## 背景及大标题反馈修订

背景不再用程序模拟粉青团块和稀疏星圈。官网的实际实现为 `#ededed` 底色、渐变图、白色图标、描边文字四层，三张图各自平铺、各自保留周期。原渐变 PNG 自带很低的透明度，因此与灰底叠加后是淡灰粉青，保留其原始透明度。1000px 输出按官网 1024px 断点使用 SP 素材；宽图使用 PC 素材，PC 渐变至少 1920px 宽且居中，图标保持 912px 宽。按进程懒加载并缓存源图，直接绘入最终画布。

公共背景函数及 `outputFinalCanv` / `outputFinalBuffer` 接受 `backgroundStyle: 'guide' | 'legacy'`。原版模式保留 `bg_object_big.png`、`#fef3ef` 暖底和原有纹理比例；长图仍采用只装饰顶部的轻量模式。两版比较图生成于 `cache/guide-style-validation/revision-*`。用户看图后选择右侧的项目原背景，默认入口已设为 `legacy`；官网背景可通过显式传入 `guide` 使用。

同时检查了 [BanG Dream! 游戏页](https://bang-dream.com/game/)：其大标题为大号斜体渐变英文、小号副标题及右侧笔画与星形装饰。按用户允许保留原风格的意见，整页大标题恢复项目原先的粉色胶囊叠白色底带；不再使用上一版左上灰色小字和下方粉色大字的方案。长标题仍在原位图槽内单行缩放。

GUIDE `.sub-Section_Heading` 右侧背景是原始 `bg_dot_right-end.png`，并非整页 `.sw-Heading_Icon` 的星形。按反馈移除误加的白星及手画圆点，直接采用官网淡白多边形点阵：原图 176×110，显示 125×78.125，右下对齐且不平铺，保留原 alpha。固定 70px 标题槽裁掉超出的顶部，侧标题将同一装饰随文字旋转。

## 布局与接口兼容

- 纵向数据块仍为子图最大宽度 + 200px，内容从 x=100 开始；上下共 100px 留白，有标题时额外占 70px。
- 横向数据块仍为子图宽度之和 + 200px，标题增加 70px；内容 y=50。侧标题和正文共用完整圆角轮廓，修复原来的底部裁切。
- 无背景 `BG=false` 保持透明并继承子图的装饰元数据；嵌套有背景卡片会先绘制子图阴影。
- `topLeftText=null` 与未传标题一致，兼容现有卡池调用。长标题在固定槽内测量并缩放，避免 Skia 的自动换行裁掉文字。
- `opacity` 仍由调用者决定；默认正文白底透明度为 0.9。横向卡片现在也正确采用该参数。
- `maxWidth` 在原数据块实现中未生效，本次不改变它的语义。
- 列表 key 和共用标签恢复原项目 `#5b5b5b` 实心底、白字，保留当前尺寸与胶囊外形。显式标签填色、文字色、属性色、难度色和曲线色仍优先。图表配置只作用于本次绘制，不修改 Chart.js 全局默认值。
- `useNoneBG` 显式选择纯底；自定义背景仍通过 `useEasyBG=false` 与 `BGimage` 一起启用。尺寸回退不会覆盖这些显式选择。
- 文章标题采用同一套粉色标题和深灰副标题，保留 130px 高度和活动 Logo 的空间。
- 玩家信息卡仍在 y=900 与插画叠合；原标题位图自带承托层，底部阴影留白随公共阴影宽度更新，逻辑高度不变。

## 覆盖与验证

共享数据块被 36 个业务视图直接使用，并被歌曲、活动、卡池和玩家等专用公共块间接调用。一次公共样式变更会覆盖查询、排行、计算结果和文章图片；游戏卡面、服务器标识、稀有度及难度颜色保留原含义。

验证包含 TypeScript 构建和实际 PNG/JPEG 输出。代表场景为活动 310、歌曲 3、火加成、控分结果和活动预览；公共层额外检查长标题、横向短内容、空提示、无标题卡池、0.75 透明度、透明拼接、嵌套缩放、纯底/自定义底和无圆角阴影。预览与临时验证脚本保存在被 Git 忽略的 `cache/guide-style-validation/`。

已有 `scripts/benchJpegParams.ts` 等待已被注释掉的 `mainAPI.metaCache`，无法作为此次验证入口。验证使用主表实际完成初始化后的业务绘制函数。Windows 上 Skia 的 GPU 预览进程收尾可能异常，临时验证采用 CPU 渲染；生产最终输出原本就使用 CPU。
